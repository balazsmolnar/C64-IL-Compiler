# C64Presentation art

Every picture the deck can use. All of them are generated by a script and
declared in `../Assets.cs`. The budget is 18 KB of compressed images.

- **The storyboard's asset list** (DECK.md, round 2: A1, A2, A3, A5, A6)
  comes to **9,857 bytes**. These are always declared.
- **Extras** come to **4,427 bytes**: a title picture, logos, pipeline
  diagram pieces and section icons. They are built and ready, but declared
  only under `#if SCENE_ART || ART_EXTRAS`, so they cost no program memory
  until a slide wants one. To use one, move its line out of the `#if`.
- **Everything together: 14,284 bytes.**

## Pictures on the disk

A1, A2 and A3 (9,073 bytes) are not embedded. `presentation_art.py` also
writes them, the same compressed bytes, to `art/build/disk/*.bin`, and
`../disk.txt` lists them, so the build writes `prg/presentation.d64` with
the program and the files `shotroom`, `shottitle` and `shotboss`
(`tools/make-d64.ps1`, run by `tools/compile-and-assemble.bat`). The script
also writes `art/build/picture_buffer.asm`: one buffer, `buf_Picture`,
sized for the largest picture (3,755 bytes). `art/ArtDisk.cs` loads a
picture into it and returns the address for `DrawImage`:

    C64.Screen.DrawImage(0, 0, ArtDisk.Load(DiskPicture.ShotRoom));

Call it while the previous slide is still showing: the screen stays as it
is during the load. A picture already in the buffer is not loaded again; a
failed load draws nothing. Load times, measured with `-Scene DISK -Slide
0/1/2` (`art/DiskScene.cs`, which prints them): A1 10.1 s, A2 7.6 s, A3
7.3 s on a 1541 (VICE true drive emulation, `presentation-shot.ps1 -Drive
True`); 0.2-0.3 s on VICE's virtual drive (`-Drive Virtual`).

## Regenerating

    python C64Presentation/art/presentation_art.py

This one entry point draws every asset as a PNG in exact C64 colours
(`art/src/<name>.png`) and converts it with `tools/c64img.py` into
`art/build/<name>.img`, the file the .csproj embeds. It also writes
`art/src/<name>.c64.png` (what the C64 will show) and
`art/src/pipeline_layout.png`, then prints the size table. It needs
Python 3 + Pillow, plus the Windows fonts Segoe UI / Segoe UI Bold /
Segoe UI Semibold (`C:\Windows\Fonts`) for the large lettering. That
lettering is drawn 4x larger, scaled down and thresholded, so round
letters have no stair steps. Small lettering (the code card, "C#"/"IL" on
the pipeline pages) uses the 8x8 pixel font in the script.

The Catacombs screenshots are converted from pixel-exact VICE frames, which
are checked in under `art/src/shots/`. These are VICE's own frame buffer
(384x272 with the border; the screen starts at 32,35), not a window capture
with the CRT filter. Capturing them again is slow, needs VICE and opens one
minimised VICE window per scene, so `presentation_art.py` does not do it.
Nothing under `Catacombs/` is changed by it. It builds the scene without
the extra VICE window of `catacombs-shot.ps1` and grabs every listed time
from one minimised instance.

    python C64Presentation/art/catacombs_shots.py      # uses vice_grab.py

| Frame | Scene build, emulated time | Used for |
|---|---|---|
| MONSTERROOM_12.png | `MONSTERROOM`, 12 s: the player and the skeleton guardian in combat | A1 |
| FLOW_6.png | `FLOW`, 6 s: the title screen | A2 |
| COMBAT_10.png | `COMBAT`, 10 s: the Bone Warden encounter | A3 (horn bases de-speckled by `flatten_horns`) |

## Reviewing on the C64

    & "<root>\tools\presentation-shot.ps1" -Root "<root>" -Scene ART -Slide N -OutPrefix "<root>\.debug-tmp\art\pageN_"

`-Scene ART` makes `Program.Main` call `art/ArtScene.cs` (one `#if` line),
which shows art page N and holds it. ArtScene doubles as a worked example of
drawing every asset.

| N | Page |
|---|---|
| 0 | title (extra) |
| 1 | logos + section icons (extras) |
| 2 | pipeline diagram (extras) |
| 3 | A1 with a caption band (split at 21) |
| 4 | A3 (split at 15) |
| 5 | A2 full screen |
| 6 | A5 + A6, all hi-res |

## Palette (dark theme)

| Role | C64 colour | `Colors` / number |
|---|---|---|
| Slide background | black | 0 |
| Surface (cards, panels) | dark grey | `Grey1` = 11 |
| Rules, muted text, inactive | mid grey | `Grey2` = 12 |
| Body / secondary text | light grey | `Grey3` = 15 |
| Titles, primary text | white | 1 |
| **Accent** (arrows, highlights, icons) | cyan | 3 |
| Second accent, sparingly | yellow | 7 |
| Brand only (C# / .NET marks) | violet | 4 |

Some art uses colours of its own: the breadbox badge (light red, yellow,
light blue), the monitor screen (blue / light blue) and the C64 logo
(light blue / light red). The screenshots keep the game's own colours.
Matching `DrawText` matrix bytes: `0x10` white on black, `0xF0` light grey,
`0x30` cyan, `0x1B` white on a card.

## Modes

Multicolour and hi-res mix only through a raster split. Everything here is
hi-res except A1, A2 and A3:

- **A1**: `SetScreenMode(MultiColor)`, `DrawImage(0, 0, img_ShotRoom)`,
  then `SetSplit(21, ScreenMode.Bitmap)`. Rows 21-24 are hi-res.
- **A2**: `SetScreenMode(MultiColor)`, `DrawImage(2, 3, img_ShotTitle)`.
  Full screen, no split, no text. It is 36x18 and centred, leaving 3 empty
  rows above and 4 below.
- **A3**: `SetScreenMode(MultiColor)`, `DrawImage(0, 0, img_ShotBoss)`,
  then `SetSplit(15, ScreenMode.Bitmap)`. Rows 15-24 are hi-res.
  **Suggestion:** put the boss's name under it in hi-res with
  `DrawText(12, 16, "THE BONE WARDEN", 0x30)` (cyan, centred). The game's
  own name banner is outside the crop.
- Call `ClearSplit()` before going back to `SetScreenMode(Bitmap)`. The
  multicolour background ($D021) must be black.

Every image assumes a black slide background. Logos, icons and extras have
transparent surroundings, which `DrawImage` leaves untouched.

**A6 is pixels only** (`--planes b`). It stores no colours, so it takes the
colours its cells already have: set them first, e.g.
`SetCellColors(col, row, 3, 3, 0x30, Colors.Black)` for cyan on black, or
the section slide's own colours. Ink = the high nibble.

## Assets

The label is used as `C64Address.FromLabel("img_<Label>")`; A1-A3 are
on the disk instead and are drawn with `ArtDisk.Load(DiskPicture.<Label>)`.

## Known weaknesses

- **A1:** in the `MONSTERROOM` scene the player and the skeleton are always
  in combat, one above the other in the doorway. At 6-13 s they never stand
  apart; at 12 s the skeleton stands out most clearly above the player.
  Separating them would need a different scene build, and Catacombs is
  read-only here.
- **A3:** rows 0-14 cut the skull at the teeth. The slide draws the name in
  hi-res on row 16 instead of showing the game's banner.
- **Screenshot compromises:** the Catacombs sprites are merged into the
  multicolour bitmap. A few cells needed a colour compromise: 7 in A1, 12 in
  A2 and 7 in A3 (around the player, the title glints and the boss's eyes).
  Hi-res sprite pixels were halved to multicolour width.
- **A5:** hi-res allows two colours per cell, so the dome is suggested by
  rounded corners, a highlight and a crease rather than shaded.
- **Extras:** the pipeline labels in row 4 sit right under the icons. There
  is no bezel/screen-frame graphic: with one raster split, a framed
  multicolour shot inside a hi-res slide is not possible.
- The large lettering is Segoe UI, not the engine's font.
